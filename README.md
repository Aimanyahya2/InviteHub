# منصة إدارة الدعوات (نسخة متعددة المستأجرين - Multi-Tenant)

منصة White-Label لإدارة الدعوات الإلكترونية، مبنية عشان تُباع لعدة عملاء (موزّعين/مصممين) في نفس الوقت، كل واحد منهم له:

- دومين خاص به (أو نطاق فرعي مؤقت لحد ما يربط دومينه)
- حساب دخول منفصل تمامًا، وبياناته (مناسباته ومدعوينه) معزولة بالكامل عن باقي المستأجرين
- شعار ولون أساسي خاص به يظهر في لوحته وفي صفحة الدعوة العامة لمدعويه

وأنت (**المشرف العام**) عندك لوحة منفصلة تدير منها كل المستأجرين: تنشئ حساب جديد، تربط له دومين، تحدد باقته، وتوقفه أو تحذفه وقت ما تبي.

## المفاهيم الأساسية

| المصطلح | يعني إيش |
|---|---|
| **المشرف العام (Super Admin)** | أنت، مالك المنصة. يدخل من `/super-admin/login` بغض النظر عن الدومين. |
| **المستأجر (Tenant)** | عميلك (مصمم أو منظّم مناسبات) اشترى وصول للمنصة تحت دومينه الخاص. |
| **أدمن المستأجر** | الحساب اللي يستخدمه عميلك (أو أنت نيابة عنه بالبداية) لإدارة مناسباته من `/admin`. |

## المتطلبات

- Node.js 18 أو أحدث
- سيرفر VPS، ودومين رئيسي للمنصة (تُبنى عليه نطاقات فرعية تلقائية مثل `lamsa.yourplatform.com`)، بالإضافة لإمكانية ربط دومين مخصص كامل لكل مستأجر لاحقًا

قاعدة البيانات SQLite (ملف واحد) — بدون سيرفر قاعدة بيانات منفصل.

## التشغيل محليًا (للتجربة)

```bash
npm install
cp .env.example .env
# عدّل .env: بيانات دخول المشرف العام + PLATFORM_ROOT_DOMAIN
npm run seed      # ينشئ حساب المشرف العام فقط (المستأجرون يُنشأون من داخل لوحته)
npm start
```

افتح `http://localhost:3000/super-admin/login` وسجّل دخول بحساب المشرف العام، وأنشئ أول مستأجر من هناك.

للتجربة المحلية بدون دومين حقيقي، تقدر تحاكي أي نطاق فرعي بتعديل ملف `hosts` في جهازك (`127.0.0.1 lamsa.platform.test`) أو باستخدام أداة مثل curl مع `-H "Host: lamsa.platform.test"`.

## هيكلة المشروع

```
server.js                نقطة الدخول + توجيه المسارات
db/index.js                قاعدة البيانات: tenants, admins, events, guests
db/seed.js                  إنشاء حساب المشرف العام الأول فقط
middleware/tenant.js         يحدد المستأجر الحالي بناءً على الدومين في كل طلب
middleware/auth.js            حماية لوحة المستأجر ولوحة المشرف العام كل على حدة
routes/superadmin.js          لوحة المشرف العام: إنشاء/تعديل/إيقاف/حذف المستأجرين
routes/auth.js                  تسجيل دخول/خروج أدمن المستأجر (مرتبط بدومينه)
routes/admin.js                  كل شاشات إدارة المناسبات (معزولة تلقائيًا لكل مستأجر)
routes/public.js                  صفحة الدعوة العامة وتأكيد الحضور (مع شعار ولون المستأجر)
views/                            كل القوالب (super_* للمشرف العام، البقية لأدمن المستأجر)
```

## آلية عزل البيانات (كيف نضمن ما يشوف مستأجر بيانات غيره)

1. كل طلب لأي صفحة تحت `/admin` أو `/login` يمر أولًا على `middleware/tenant.js`، اللي يقرأ اسم الدومين من الطلب (`Host` header) ويحدد المستأجر المطابق من جدول `tenants`.
2. كل استعلام قاعدة بيانات في `routes/admin.js` يشترط `tenant_id = req.tenant.id` — حتى لو حاول حد تخمين رقم مناسبة يخص مستأجر ثاني، يرجع له 404.
3. جلسة الدخول (`session.admin`) مربوطة بـ `tenant_id`، فحتى لو نفس المتصفح، دخول من دومين مستأجر A ما يشتغل على دومين مستأجر B.

هذا تم اختباره فعليًا (محاولة وصول مباشر لمناسبة مستأجر آخر برقمها، ومحاولة إعادة استخدام جلسة دخول عبر دومين مختلف) — كلاهما محجوب بشكل صحيح.

## رفع المشروع على VPS

### 1. تجهيز DNS

- وجّه الدومين الرئيسي وواحد Wildcard نحو IP السيرفر:
  ```
  A     yourplatform.com          -> IP السيرفر
  A     *.yourplatform.com        -> IP السيرفر   (يغطي كل النطاقات الفرعية تلقائيًا)
  ```
- لكل مستأجر يبي دومين مخصص كامل (مو نطاق فرعي من عندك)، يوجّه هو من طرفه A Record لنفس IP السيرفر.

### 2. رفع الملفات وتثبيت الحزم

```bash
scp -r invite-platform user@your-server-ip:/var/www/
cd /var/www/invite-platform
curl -fsSL https://deb.nodesource.com/setup_20.x | sudo -E bash -
sudo apt-get install -y nodejs
npm install --production
cp .env.example .env
nano .env   # عدّل SESSION_SECRET, SUPER_ADMIN_USERNAME/PASSWORD, PLATFORM_ROOT_DOMAIN
npm run seed
```

### 3. تشغيل مستمر عبر PM2

```bash
sudo npm install -g pm2
pm2 start server.js --name invite-platform
pm2 save
pm2 startup
```

### 4. Nginx: دومين رئيسي + Wildcard + دومينات مخصصة

كل الدومينات (الرئيسي، الفرعية، والمخصصة لكل مستأجر) تشير لنفس تطبيق Node — التطبيق نفسه يفرز المستأجر حسب اسم الدومين، فإعداد Nginx واحد يكفي للجميع:

```nginx
server {
    listen 80;
    server_name yourplatform.com *.yourplatform.com;

    location / {
        proxy_pass http://localhost:3000;
        proxy_http_version 1.1;
        proxy_set_header Host $host;
        proxy_set_header X-Real-IP $remote_addr;
        client_max_body_size 10M;
    }
}
```

لما مستأجر يربط دومين مخصص كامل (مو فرعي من عندك)، أضف `server_name` بنفس الطريقة ضمن نفس البلوك أو بلوك جديد يشير لنفس `proxy_pass` — التطبيق يتعرف عليه تلقائيًا طالما مسجل في جدول `tenants` من لوحة المشرف العام.

```bash
sudo ln -s /etc/nginx/sites-available/invite-platform /etc/nginx/sites-enabled/
sudo nginx -t && sudo systemctl reload nginx
```

### 5. SSL لكل الدومينات

```bash
sudo apt install certbot python3-certbot-nginx
# للدومين الرئيسي + Wildcard (يحتاج تحقق DNS وليس HTTP، بعض مزودي DNS يدعمونه عبر certbot plugins)
sudo certbot --nginx -d yourplatform.com -d *.yourplatform.com

# لكل دومين مخصص لمستأجر جديد، أضفه لاحقًا بنفس الطريقة:
sudo certbot --nginx -d invites.tenant-domain.com
```

## سير العمل (كيف تبيعها فعليًا)

1. تسجّل دخول لوحة المشرف العام (`/super-admin/login`).
2. تنشئ مستأجر جديد لكل عميل جديد يشتري الخدمة — تحدد اسمه، نطاقه الفرعي المبدئي (أو دومينه المخصص إذا جاهز)، الباقة، وتنشئ له حساب دخول أولي.
3. ترسل للعميل رابط دخوله (`https://اسمه.yourplatform.com/login`) وبيانات الدخول.
4. العميل (أو أنت نيابة عنه) يدخل لوحته، يضيف مناسباته، يرفع تصاميمه، يدير مدعوينه — بمعزل تام عن أي عميل ثاني.
5. لو العميل جهّز دومين خاص لاحقًا، ترجع للوحة المشرف العام وتحدّث حقل "دومين مخصص" لحسابه — يشتغل فورًا بدون أي تعديل تقني إضافي.
6. لو توقف عميل عن الدفع، توقفه بضغطة زر من لوحته ("موقوف") بدون حذف بياناته، أو تحذفه نهائيًا لاحقًا.

## تصنيف المناسبات

المنصة تخدم أي نوع مناسبة أو فعالية أو تجمّع بدون أي قيد (اسم المناسبة حقل نص حر بالكامل). بالإضافة لذلك، كل مناسبة تُصنّف بنوع (من قائمة جاهزة: زفاف، خطوبة، تخرج، عيد ميلاد، مؤتمر، اجتماع عمل، فعالية خيرية، مناسبة رسمية — أو نوع مخصص يكتبه المستخدم بنفسه). هذا التصنيف يظهر كفلاتر بلوحة التحكم الرئيسية لكل مستأجر، ويقدر يتابع منه عدد المناسبات لكل نوع.

## المرحلة القادمة: إرسال واتساب تلقائي بالكامل

حاليًا الإرسال عبر زر "wa.me" اليدوي لكل مدعو (بدون تكلفة، لكن يدوي). للانتقال لإرسال جماعي تلقائي لكل مستأجر:

1. أضف حقول `whatsapp_api_key` / `whatsapp_provider` لجدول `tenants` (كل مستأجر يربط حسابه الخاص عند مزود مثل WATI أو 360dialog).
2. أضف زر "إرسال جماعي" في `routes/admin.js` يستدعي API المزود لكل مدعو دفعة وحدة بدل واحد واحد.

هذا الجزء غير منفّذ حاليًا لأنه يحتاج حساب فعلي عند مزود API وبيانات اعتماد حقيقية لكل مستأجر.
